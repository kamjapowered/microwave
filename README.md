<h1 align="center">microwave</h1>

<p align="center">
  <strong>opt-in umbrella packages for go modules</strong>
</p>

---

`microwave` is a small go cli that scans tagged declarations across one or more packages and emits a single umbrella `.go` file that re-exports them:

```sh
microwave <path>... --out <file> --pkg <name>
```

the goal is to give downstream consumers one import path that covers the ~90% of your public api you actually want them to reach for, without hand-maintaining a re-export file.

## install

```sh
just install
```

this builds and installs `microwave` into `~/.local/bin/microwave`.

## tagging

re-export is opt-in. nothing leaves your package unless it carries a tag. write `//microwave:export` as the last line of the declaration's doc comment, separated from the prose by a blank `//`:

```go
// Foo does the thing.
//
//microwave:export
type Foo struct{ Name string }
```

this is the form `gofmt` produces (it treats `//microwave:export` as a directive and parks it just above the decl), so it survives saves and re-runs.

a second token after `export` overrides the name in the umbrella — useful for resolving collisions when two packages each export a `Foo`:

```go
// Foo is renamed to Bar in the umbrella.
//
//microwave:export Bar
type Foo struct{}
```

tags apply to individual declarations. for `var ( … )`, `const ( … )`, and `type ( … )` blocks, tag the spec inside the block, not the keyword.

## what gets emitted

| source decl                       | umbrella emission                                        |
| --------------------------------- | -------------------------------------------------------- |
| exported type (incl. generic)     | `type Foo = pkg.Foo`                                     |
| exported var                      | `var Foo = pkg.Foo`                                      |
| exported const                    | `const Foo = pkg.Foo`                                    |
| exported func (incl. generic)     | wrapper func that forwards to `pkg.Foo`                  |
| methods on a re-exported type     | ride along with the type alias — no separate tag needed  |

## a taste

input:

```go
// api/a/a.go
package a

// Foo does the thing.
//
//microwave:export
type Foo struct{ Name string }

// Hello says hi.
//
//microwave:export
func Hello(name string) string { return "hi " + name }
```

```go
// api/b/b.go
package b

// Baz is a constant.
//
//microwave:export
const Baz = "baz"
```

invocation:

```sh
microwave ./api/... --out umbrella.go --pkg umbrella
```

output:

```go
// Code generated by microwave. DO NOT EDIT.

//go:generate microwave ./api/... --out umbrella.go --pkg umbrella

package umbrella

import (
	a "example.com/mod/api/a"
	b "example.com/mod/api/b"
)

// Foo does the thing.
type Foo = a.Foo

// Baz is a constant.
const Baz = b.Baz

// Hello says hi.
func Hello(name string) string { return a.Hello(name) }
```

drop the invocation into a `//go:generate` line and `go generate ./...` regenerates the umbrella whenever your tags change.

## good to know

- nothing is exported unless you tag it.
- re-running on the same input produces byte-identical output, so the umbrella diffs cleanly in vcs.
- when a tagged func takes a parameter whose type you have also tagged, the wrapper uses your umbrella name — consumers see one consistent surface.
- if a tag would produce a file that can't compile (unexported source names, unexported types leaking into a func signature, etc.), microwave refuses to write the file and tells you which tag is at fault.

run `microwave --help` for the full flag list.
